# دليني الأقصى (Dalini Aqsa)

نسخة جديدة كاملة من تطبيق دليني، بتصميم مختلف بالكامل وحركات وتأثيرات، وتسجيل الدخول بالبريد الإلكتروني فقط.

## البنية
```
backend/    خادم Node.js (بدون Express) - تسجيل، دخول، استرجاع كلمة مرور، طلبات، عروض
app/        تطبيق Flutter (مصدره الوحيد: app/lib)
.github/workflows/build-apk.yml   بناء APK تلقائي عند الرفع لفرع dalini-aqsa
```

## تشغيل الخادم محلياً
```
cd backend
npm install
cp .env.example .env   # عدّل القيم داخل .env
npm start
```
بدون `DATABASE_URL` يعمل الخادم بالذاكرة (للتجربة فقط، يُفرّغ عند إعادة التشغيل).
بدون مفتاح بريد (`RESEND_API_KEY` أو `BREVO_API_KEY`) لا يُرسل بريد حقيقي، ويظهر تحذير في السجل.

## اختبار الخادم
```
cd backend
npm test
```
اختبار شامل (62 حالة) يغطي: التسجيل، الدخول، استرجاع كلمة المرور بالبريد، الطلبات، العروض، قبول العرض، مسار تنفيذ الفني، الصلاحيات، وتحديد معدل الطلبات.

## نشر الخادم (Render أو مماثل)
- Build Command: `cd backend && npm install`
- Start Command: `cd backend && npm start`
- متغيرات البيئة: كما في `backend/.env.example` (يُنصح بإضافة `DATABASE_URL` لقاعدة PostgreSQL حقيقية، وإلا تُفرّغ البيانات عند كل إعادة تشغيل)

## بناء تطبيق Flutter
```
cd app
flutter pub get
flutter run --dart-define=API_URL=https://your-backend-url
```
لبناء APK جاهز للتوزيع، إما محلياً:
```
flutter build apk --release --dart-define=API_URL=https://your-backend-url
```
أو تلقائياً عبر GitHub Actions: ادفع هذا المجلد إلى فرع اسمه `dalini-aqsa` في مستودعك، وسيبني الـWorkflow ملف APK ويرفعه كـ Artifact جاهز للتحميل من صفحة Actions.

## ملاحظات أمان
- كلمات المرور محفوظة بـ scrypt (salt عشوائي لكل مستخدم)، وليست بنص واضح.
- رموز استرجاع كلمة المرور مكوّنة من 6 أرقام، صالحة 10 دقائق، ومحمية بحد للمحاولات ومهلة 60 ثانية بين الطلبات.
- استجابة "نسيت كلمة المرور" واحدة لكل من البريد المسجل وغير المسجل (لا تكشف من مسجّل).
- الفني لا يرى بيانات العميل (الاسم/العنوان الدقيق) إلا بعد قبول الزبون لعرضه.
- جميع الجداول ببادئة `aq_` كي لا تتعارض مع أي مشروع قديم يستخدم نفس القاعدة.
